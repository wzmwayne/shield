锁盾（Shield）保护措施完整清单

本文档列出锁盾需要实现的全部保护措施。所有条目均为推荐性建议，实现方可依据实际场景调整。目标设备 Android 9+。

---

一、对抗锁机病毒

1. 锁屏调用监控
监听非系统应用调用 lockNow() 的行为。当检测到非信任应用在短时间内多次调用锁屏，或用户未主动操作时屏幕被锁定，触发 L4 恢复流程。

2. 全屏覆盖层检测
监听窗口层级变化，识别非系统应用创建的 TYPE_APPLICATION_OVERLAY 或 TYPE_SYSTEM_ALERT 级别全屏窗口。若覆盖层遮挡系统 UI（锁屏、设置、权限对话框），触发锁机嫌疑评估。

3. 锁屏密码篡改检测
通过设备所有者身份定期校验锁屏密码策略是否被非用户操作修改。若检测到密码被恶意更改，触发 L4 恢复。

4. 密码恢复重置
检测到锁机行为时，通过 resetPasswordWithToken 强制重置锁屏密码，默认重置为 123456 或 1234。理由：覆盖层显示可能失败，随机密码会导致变相锁机。重置前临时降低密码质量要求，重置后恢复原策略，并提示用户尽快修改为强密码。

5. 恢复信息悬浮展示
通过 TYPE_ACCESSIBILITY_OVERLAY 在恶意覆盖层之上显示恢复密码和处置指引，确保用户即使被覆盖层遮挡也能看到恢复信息。

6. 锁屏状态下的前台焦点监控
设备进入锁屏状态后，若非系统应用持续持有前台焦点，判定为锁机嫌疑，触发 L3 强制停止。

---

二、对抗无障碍病毒

7. 无障碍服务白名单强制
通过 setPermittedAccessibilityServices 设定白名单。不在列表中的非系统无障碍服务无法被启用，即使 Shell 修改了 enabled_accessibility_services，系统白名单仍会阻止其实际运行。

8. 无障碍服务启用监控
监听 enabled_accessibility_services 的变化。当检测到非白名单服务被尝试启用时，记录并告警。若检测到锁盾自身被移出列表，立即通过 WRITE_SECURE_SETTINGS 重写恢复。

9. 无障碍行为分析
通过锁盾自身的无障碍服务，监听其他无障碍服务的模拟点击行为。检测高频点击（5 秒内超过 10 次）、跨应用连续操作（30 秒内切换超过 5 个应用）、系统设置页面反复点击授予类按钮等异常模式。

10. 无障碍服务动态切断
白名单内服务若行为异常，通过设备所有者身份将其移出白名单，系统立即切断其无障碍能力。

11. 无障碍服务保活
参考 luqijun9/AccessibilityManager fork 版，实现崩溃检测（假死检测）、解锁检测、定时检测（≥5 分钟）、延迟 1 秒保活、重启强杀 app 等保活机制。

12. 无障碍白名单原子更新
每次更新白名单前先枚举当前已启用服务，构建包含锁盾自身在内的完整新列表，一次性提交。锁盾自身包名硬编码进构建逻辑，避免自锁。

---

三、对抗恶意设备管理器

13. 设备管理器激活监控
监听 ACTION_DEVICE_ADMIN_ENABLED 广播，检查激活包是否在信任列表中。

14. 非白名单设备管理器撤销
非白名单应用激活设备管理器时，通过 removeActiveAdmin 强制撤销。此操作由设备所有者执行，系统强制执行，恶意应用无法拒绝。

15. 设备管理器列表定期校验
通过设备所有者身份定期枚举所有活跃设备管理器，检测是否有新增的非白名单项。

16. 设备管理器权限组合告警
当应用同时请求设备管理器 + 无障碍权限，或设备管理器激活后立即请求无障碍权限时，触发 L3 撤销 + 告警。

---

四、对抗悬浮窗与覆盖层

17. 覆盖层创建监控
监听窗口层级变化，检测非系统应用创建全屏窗口的行为。通过设备所有者通道查询该应用的 SYSTEM_ALERT_WINDOW 权限状态。

18. 非信任覆盖层告警
非信任应用创建全屏覆盖层时，触发 L2 告警，在通知栏和悬浮窗提示用户。

19. 覆盖层遮挡系统 UI 处置
覆盖层遮挡锁屏、设置、权限对话框等系统 UI 时，触发 L3 强制停止该应用。

20. 覆盖层 + 锁屏组合处置
全屏覆盖层 + 锁屏调用同时出现时，判定为锁机行为，触发 L4 恢复流程。

21. 按需禁止窗口创建
检测到可疑 Shell 活动或 L3/L4 阻断时，临时启用 DISALLOW_CREATE_WINDOWS，阻止非系统应用创建窗口。处置完成后恢复。

---

五、对抗 Shell 权限

22. 防止 ADB 移除设备所有者
锁盾的 Manifest 中不声明 android:testOnly="true"，确保 dpm remove-active-admin 命令失败并抛出 SecurityException。

23. 阻止卸载
调用 setUninstallBlocked 保护锁盾自身及用户指定的信任应用，即使 adb shell pm uninstall 也会失败。

24. 阻止强制停止
设备所有者应用受系统保护，am force-stop 命令会被拒绝。锁盾保持设备所有者身份即可免疫。

25. 阻止禁用
设备所有者应用受系统保护，pm disable-user 会被系统拒绝。

26. 阻止安全模式绕过
按需或默认添加 DISALLOW_SAFE_BOOT 限制，禁止进入安全模式，封堵攻击者利用安全模式绕过控制的路径。注意：安全模式也是用户自救通道之一，建议仅在检测到活跃攻击时临时启用。

27. 信任应用被禁用恢复
通过 PACKAGE_CHANGED 广播检测到信任应用被 pm disable-user 禁用后，通过设备所有者身份重新启用。

28. 信任应用被强杀恢复
检测到信任应用被 am force-stop 强杀后，记录事件并触发 L3 阻断流程。

29. Shell 授予权限撤销
检测到 Shell 通过 appops set 授予非信任应用 SYSTEM_ALERT_WINDOW 等高危权限后，通过设备所有者身份撤销。

30. Secure Settings 篡改恢复
检测到 enabled_accessibility_services 被修改且不包含锁盾自身时，通过 WRITE_SECURE_SETTINGS 直接重写恢复。

31. ADB 活动时间线记录
监听 ADB 连接相关的系统 UI 事件，记录 Shell 活动时间线，供用户查看。

32. 按需应用控制限制
检测到可疑 Shell 活动时，临时启用 DISALLOW_APPS_CONTROL、DISALLOW_UNINSTALL_APPS，事后恢复。

---

六、对抗 MDM 组件

33. 阻止 MDM 成为设备所有者
Android 系统只允许存在一个设备所有者。锁盾占据此位置后，MDM 的 dpm set-device-owner 请求会失败。

34. 压制 MDM 配置文件所有者
若 MDM 作为配置文件所有者存在，锁盾可通过 setApplicationHidden 隐藏 MDM 应用、setUserRestriction 限制其功能、或冻结整个工作资料来使其失效。

35. MDM 应用监控
将 MDM 应用纳入威胁评估范围，检测其激活设备管理器、请求无障碍、创建覆盖层等行为。

---

七、对抗恶意包安装

36. 新安装应用权限声明监控
新安装应用声明 BIND_DEVICE_ADMIN + BIND_ACCESSIBILITY_SERVICE 时，触发 L2 告警。

37. 安装后快速授权监控
新安装应用在安装后 60 秒内请求无障碍权限，触发 L3 阻止启用。

38. 高危权限组合告警
新安装应用请求 SYSTEM_ALERT_WINDOW + 无障碍权限组合时，触发 L2 告警。

39. 安装对话框感知
通过无障碍事件流感知安装确认对话框的出现，关联到触发它的前台应用。

---

八、自我保护

40. 设备所有者身份保护
不声明 testOnly，确保 ADB 无法移除设备所有者身份。

41. 进程存活保护
设备所有者功能由系统服务托管，不依赖应用进程。进程被强杀后，系统自动重启无障碍服务，保活层触发重启。

42. 无障碍服务保活
通过 WRITE_SECURE_SETTINGS 检测并恢复自身无障碍服务，参考 fork 版保活机制。

43. 自身卸载保护
通过 setUninstallBlocked 阻止自身被卸载。

44. 自身权限保护
确保 WRITE_SECURE_SETTINGS 在激活时被正确授予，并在运行时定期校验其有效性。

45. 白名单自锁防护
无障碍白名单更新时硬编码自身包名，避免将自己排除在外导致失去感知能力。

---

九、用户数据与设备保护

46. 输入法白名单
通过 setPermittedInputMethods 设定输入法白名单，仅保留系统输入法和用户确认的输入法，阻断恶意输入法模拟输入。

47. 密码策略临时调整
密码恢复重置前，若当前策略不允许简单数字密码，临时降低密码质量要求，重置后恢复原策略。

48. 恢复令牌预置与备份
激活时调用 setResetPasswordToken 预置恢复令牌，引导用户导出备份，提供恢复演练验证令牌可用性。

49. 网络管控（仅阻断时）
L3/L4 阻断触发时临时断网，通过 DISALLOW_CONFIG_MOBILE_NETWORKS 限制移动网络配置，或通过设备所有者 API 禁用 Wi-Fi。处置完成后恢复网络。

50. 调试管控（仅阻断时）
L3/L4 阻断触发时临时添加 DISALLOW_DEBUGGING_FEATURES，完全禁用调试功能包括 USB 调试。处置完成后移除，恢复 ADB 使用。默认不阻断 ADB，以支持用户对 Shizuku 等工具的日常使用。

51. 不阻止恢复出厂设置
锁盾不阻止用户通过系统设置或 Recovery 模式执行恢复出厂设置。恢复出厂设置会清除锁盾自身，但同样会清除攻击应用，用户由此获得干净设备。锁盾不配置 FactoryResetProtectionPolicy 来拦截恢复出厂设置。不在恢复中心模块中引导用户执行恢复出厂设置，但也不阻止。

52. 不阻止刷机
锁盾不设计任何防刷机机制。Recovery 双清、EDL/EUB 刷机等均不干预，这些操作会连同攻击应用一起清除。

---

十、威胁评估与阻断

53. 事件聚合
所有感知层事件进入事件队列，按时间窗口聚合。每个事件包含事件类型、来源包名、时间戳、上下文。

54. 风险评分
每个事件类型有基础风险分。聚合后根据来源是否在白名单中、事件频率、事件组合、当前设备状态加权。

55. 分级决策
L1 观察（记录日志）、L2 告警（通知栏 + 悬浮窗）、L3 切断（移出白名单 / 撤销设备管理器 / 强制停止 / 断网 / 临时禁用调试）、L4 恢复（重置密码 / 隐藏恶意应用 / 断网 / 临时禁用调试 / 悬浮窗显示恢复信息）。

56. 事件组合规则
锁机嫌疑、无障碍滥用、设备管理器攻击、权限诱导、Shell 攻击等组合规则，触发对应等级的处置。

57. 自动阻断
威胁评估引擎输出处置指令后，阻断执行器验证合法性并执行处置，记录结果，通知感知层展示。

58. 手动阻断
通知栏常驻通知、无障碍悬浮球（单击打开面板、长按紧急阻断）、应用内面板、硬件按键组合（音量上 + 音量下长按 3 秒）、锁屏恢复入口。

59. 软处置（可选）
跳转到雹进行冻结观察，为用户提供介于“观察”和“强制停止”之间的处置选项。

---

十一、恢复与容错

60. 恢复中心
显示恢复令牌状态，提供导出、恢复演练、操作记录查看。

61. 锁屏恢复流程
设备被锁机时，通过悬浮告警窗口显示恢复密码（123456/1234）。用户输入解锁后，锁盾自动执行清理流程。

62. 处置后状态恢复
断网和调试禁用是临时措施，处置完成后自动恢复，并在 UI 中提示用户当前状态。

63. 白名单错误恢复
每次更新前做合法性检查。若更新失败，保留原白名单，记录错误日志。提供“恢复默认白名单”功能，默认白名单始终包含自身服务。

64. Shizuku 掉线容错
运行时不调用 Shizuku，WRITE_SECURE_SETTINGS 永久有效，无障碍保活不受影响，设备所有者能力不受影响。

65. Dhizuku 委托容错
Dhizuku 委托模式下 Shizuku 掉线时，已建立的 Binder 代理可能仍有效，但新的设备所有者请求无法转发。UI 提示用户重新连接 Shizuku 或切换为锁盾直接持有设备所有者身份。

66. Shell 攻击期间被强杀恢复
锁盾进程被 am force-stop 强杀后，系统自动重启无障碍服务，设备所有者功能由系统服务托管。锁盾重启后根据事件日志恢复处置状态。

---

十二、激活阶段保护

67. 设备所有者激活条件检查
激活前通过 Shizuku 执行 pm list users 枚举用户，通过账户检测模块获取持有账户的应用列表。UI 分为“需处理项”和“已满足项”，提供一键跳转到雹冻结界面的引导。

68. 账户检测
通过 Shizuku 以 Shell 身份执行 dumpsys account，解析输出并映射为应用包名。若解析不稳定，降级使用 cmd package query-services -a android.accounts.AccountAuthenticator。

69. 辅助软件内置
内置 Shizuku、雹的 APK，向导中释放安装。账户检测模块建议自行实现，不依赖外部 Accounts 应用。

70. 激活后自检
验证设备所有者（或 Dhizuku 委托）有效、无障碍服务已启用且在白名单中、WRITE_SECURE_SETTINGS 已授予、恢复令牌已预置、ADB 调试仍可用。

---

十三、运行时约束

71. 运行时禁止调用 Shizuku
激活完成后，锁盾的运行时防护完全由设备所有者身份和无障碍服务身份驱动，不调用任何 Shizuku API。

72. 禁止依赖 Shell 权限的清理
锁盾严禁执行 pm uninstall、pm clear 或任何依赖 Shell 权限的清理行为。锁盾的定位是阻断威胁，清理决策由用户自行完成。

73. 默认不阻断 ADB
非阻断状态下保持 ADB 可用，支持用户对 Shizuku 及其他 ADB 工具的日常使用。仅当检测到可疑 ADB 活动或 L3/L4 阻断时临时收紧。

74. 默认不启用激进限制
DISALLOW_APPS_CONTROL、DISALLOW_UNINSTALL_APPS、DISALLOW_CREATE_WINDOWS、DISALLOW_SAFE_BOOT 等限制默认不启用，仅在检测到可疑 Shell 活动或活跃攻击时临时启用，事后恢复。
