# 响应对抗层方案（v1）

定位：感知层（无障碍）→ 威胁评估 → **响应对抗层**（执行处置）。硬约束：
① **自动处置与全局阻断都不做卸载 / 不清除数据**；「清理应用数据」「卸载」只出现在紧急处置覆盖层的**手动**按钮里，必须由用户在列表中勾选后点击；
② 默认不阻断 ADB，仅全局阻断时临时禁用且可恢复；③ 所有处置可回滚；④ 系统应用一律不参与自动处置。

> 文档状态说明：本文档已按实现更新（2026-xx）。标「✅ 已实现」的条目与当前代码一致。

---

## 一、触发方式（手动优先）

| 编号 | 触发方式 | 依赖 | 全局可用性 | 状态 |
| --- | --- | --- | --- | --- |
| T1 | **长按音量上或音量下任意一个 3 秒** | 无障碍 `flagRequestFilterKeyEvents` + `onKeyEvent` | 任意前台应用、锁屏均可 | ✅ 已实现（唯一全局入口） |
| T2 | 音量上 + 下同时长按 | 同上（组合键状态机） | 同上 | 已废弃（由 T1 取代） |
| T3 | 无障碍悬浮球长按 | `TYPE_ACCESSIBILITY_OVERLAY` | 同上 | 计划 |
| T4 | 常驻通知「紧急阻断」按钮 | 前台服务通知 | 需下拉通知栏 | 计划（低成本） |
| T5 | 应用内面板按钮（首页即面板） | 需解锁并打开应用 | 弱 | 计划（低成本） |
| T6 | 锁屏恢复入口（悬浮窗显示恢复密码） | 无障碍悬浮窗 | 锁屏 | 计划（属 L4） |

提示与防误触：**单段式**，需持续按住音量键 **3 秒**（短按无效，两次短按不会累积）；应用无法伪造硬件长按（注入需 `INJECT_EVENTS`）。
触发即反馈：**三长音递升方波提示音** + Toast + 覆盖层弹出；另两条抗关闭联动见下。
音频全部是**打进 APK 的内置方波 WAV**（`res/raw/shield_ready|trigger|alert.wav`，PCM 16bit/44.1kHz/单声道，`SoundPool` 播放，走闹钟音量通道），**不依赖任何第三方 TTS 引擎**。
**不设反悔窗口**（用户已确认）：撤销只走覆盖层「取消处置并恢复全部」或应用内自保页按钮。

## 三、白名单设计（已定稿）

- **锁盾自身**（硬编码，永不排除）
- **用户勾选的保护对象**（自保页可勾选，未勾选的第三方应用即处置对象）
- **系统应用不参与自动处置**（只作证据来源；覆盖层列表里可切「系统/所有」筛选后手动处置）
- 敏感页看护会把无障碍白名单收紧为「白名单应用 + 本应用」，离开敏感页 8 秒后自动恢复
- 已启用的输入法 / 无障碍服务（避免把用户正常使用的东西一刀切）

> 现状：还没有白名单 UI；响应层第 4/6 项必须先有它才能落地。

## 四、系统应用（预装恶意应用）处置能力边界（诚实说明）

| 手段 | 普通应用 | 预装系统应用 |
| --- | --- | --- |
| `setApplicationHidden` | ✅ | 多数可隐藏；**受保护包**（Settings / SystemUI / Launcher / 关键服务）会被系统拒绝 |
| `setPackagesSuspended` | ✅ | 通常不可挂起（not suspendable）→ 失败 |
| `pm disable-user` | 需 shell/root，**运行时禁止调用 Shizuku** → 不可用 | 同左 |
| `removeActiveAdmin` | ✅ | ✅ |
| 移出无障碍白名单 | ✅ | ✅ |
| 撤销运行时权限 | ✅ | 多数可 |
| 隐藏/断网组合 | ✅ | ✅ |

结论：**能隐藏就隐藏，隐藏不了的进「无法处置清单」**，在 UI 里列出并给一键跳转系统设置手动停用的入口
（清理动作仍由用户决定，符合「锁盾不承担清理职责」）。

## 七、已确认的决策（v1 实现口径）

| 决策项 | 结论 |
| --- | --- |
| 白名单来源 | **仅锁盾自身 + 用户勾选的保护对象**（硬编码自身；勾选项可在「自保」页管理）；其余一律视为可疑 |
| 非白名单应用处置力度 | **隐藏 + 挂起 + 撤销运行时权限 + 断网**（最激进路线） |
| 预装系统应用 | **一律不碰**（按 `FLAG_SYSTEM / FLAG_UPDATED_SYSTEM_APP` 判定，直接跳过并在清单里标注"系统应用，已跳过"） |
| 反悔窗口 | **不设**：触发即刻生效；恢复只走仪表盘「恢复」按钮（按快照回滚） |

实现要点：
- 处置对象 = 已安装的**第三方**应用 − 白名单（自身 + 勾选项）
- 每个对象依次：`setApplicationHidden(true)` → `setPackagesSuspended(true)` → 逐个撤销已授予的**运行时权限**（撤销前记录原授权清单，供恢复）
- 断网：`DISALLOW_CONFIG_MOBILE_NETWORKS`（+ 尝试 `setGlobalSetting` 关闭 Wi-Fi，厂商不支持则记入失败清单）
- 逐应用记录结果（隐藏/挂起/已撤权限/失败原因）→ 持久化成「处置清单」，UI 可见并可一键恢复
- 需要 `QUERY_ALL_PACKAGES` 才能枚举全部第三方应用（Android 11+）

## 八、自动处置响应（口径固定，不改代码）

触发即执行，全部动作**可回滚**，且**不含卸载 / 不含清理应用数据**（这两个只在覆盖层手动处置里提供）。

| 顺序 | 动作 | 实现 | 失败处理 |
| --- | --- | --- | --- |
| ① | 无障碍白名单收紧为「仅锁盾自身」 | `setPermittedAccessibilityServices([self])` | 记录失败原因，继续后续步骤 |
| ② | 关闭除自身外**全部**无障碍服务 | 重写 `enabled_accessibility_services`（原值先入快照） | 写入失败则记「WRITE_SECURE_SETTINGS 失效」 |
| ③ | 禁用开发者选项与 ADB | `DISALLOW_DEBUGGING_FEATURES` + `ADB_ENABLED=0` + `DEVELOPMENT_SETTINGS_ENABLED=0` | 缺 DO 或缺权限时如实记录 |
| ④ | 处置非白名单**第三方**应用 | `setApplicationHidden(true)` → `setPackagesSuspended(true)` → 撤销已授予的运行时权限（撤销前记录原授权） | 逐应用记录「隐藏失败/挂起失败/撤权失败:xxx」；**系统应用一律跳过并计数** |
| ⑤ | 临时断网 | `DISALLOW_CONFIG_MOBILE_NETWORKS` + 尝试 `setGlobalSetting(WIFI_ON, 0)` | Wi-Fi 不被支持时记「厂商限制」 |

处置前后：
- 处置前快照：原启用列表、ADB 状态；
- 处置后：写入「处置清单」（逐应用结果）+ 覆盖层展示流式过程与结果；
- 覆盖层按钮组提供**手动**处置：清理数据 / 再次禁用 / 恢复 / 卸载选中 / 取消处置并恢复全部；
- 恢复：按快照回滚 + 解除 `DISALLOW_*` + 取消隐藏/挂起 + 回填权限 + 恢复网络。

### 自动激活（无需用户操作，只做针对性处置）

| 触发 | 判定 | 处置 |
| --- | --- | --- |
| 进入**敏感页**（系统设置任意页面 / 应用安装-卸载器 / 权限页 / **锁盾自身所有页面**） | 包名匹配 + 类名兜底 | 立即禁用**非白名单应用**的无障碍服务 + 白名单收紧为「白名单应用 + 本应用」；**离开敏感页 8 秒后自动恢复**；30 秒冷却 |
| **非白名单（或无障碍创建的）覆盖层 ≥ 屏幕 70%** | `AccessibilityWindowInfo` 覆盖率（只算 TYPE_SYSTEM / TYPE_ACCESSIBILITY_OVERLAY，排除系统 UI、锁盾自身、白名单） | 对来源应用做**针对性阻断**（隐藏+挂起+撤权），覆盖层标题标明「自动处置（针对性）」 |

自动路径**永不执行全局处置**（不收紧全局白名单到仅自身、不禁调试、不断网、不批量处置其它应用）；全局阻断只可能由用户手势触发。

> 约束边界：自动路径 = 阻断（隐藏/挂起/撤权/断网/收紧无障碍/禁调试），**不做清理**；
> 手动路径 = 用户在覆盖层显式勾选后执行，**允许清理应用数据与卸载**（记录到事件日志与 trace）。

### 抗关闭联动（已实现）

| 场景 | 处置 |
| --- | --- |
| 锁盾无障碍**1 分钟内被关闭 3 次** | **重启无障碍服务**（写回 `enabled_accessibility_services` 并拉起前台服务，**不重启设备**）+ **执行全局阻断**；10 分钟内最多升级 3 次，避免死循环 |
| **任意阻断过程中**无障碍被关闭 | 先**中止当前阻断**（处置执行器在步骤间隙检查中止标志）→ 后台**禁用调试**（`DISALLOW_DEBUGGING_FEATURES` + `ADB_ENABLED=0` + `DEVELOPMENT_SETTINGS_ENABLED=0`）→ **重新执行全局阻断** |

> 调试通道开关位于**仪表盘「调试通道」卡片**（设置页亦有），全局阻断第 ③ 步会自动执行「禁止调试」；另配「恢复调试」按钮供测试期打开 adb。
